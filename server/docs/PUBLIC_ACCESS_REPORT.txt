if-liveSaver — Secure Public Access Implementation Report

STATUS

Implemented in the current repository. Public access remains disabled by default.
API_TOKEN is retained. No Railway deployment, production-variable changes, or paid
AI calls were made.

IMPLEMENTATION

1. Authentication

Anonymous server-managed sessions use HttpOnly, Secure, host-only cookies, hashed
credentials, CSRF protection, expiration, renewal, and revocation.

2. Workspace ownership

Ownership is saved atomically with each project. Every project route checks
authorization, including research, confirmed actions, cart, and insurance.
Inaccessible projects return 404.

3. Legacy protection

Existing project files are preserved and remain administrator-only in public
mode. Visitors cannot claim them. Disabling public mode does not expose
public-owned files through the legacy token.

4. Persistence

Sessions, quotas, reservations, and administrative audit events use SQLite on
persistent storage. Project data remains in JSON files. This requires one API
process and Node >=22.13.

5. AI quotas

Configurable defaults are five actual provider calls per UTC day, one concurrent
request per session, three global concurrent provider calls, and five workspaces
per session. Creation and both research stages are counted.

6. Cost protection

Atomic reservations precede provider calls. Returned usage reconciles estimates;
uncertain failures retain conservative charges. Separate public/admin budgets
and a persistent public-AI kill switch are implemented.

These are estimated controls, not a guaranteed billing ceiling.

7. Administrator access

An independent private key establishes a separate, expiring administrator cookie.
Protected APIs support usage inspection, pausing public AI, and reviewing legacy
projects.

8. Frontend

Automatic session initialization, no token form in public mode, quota messages,
session renewal, and administrator sign-in/out are implemented. Public project
summaries stay in memory. Identity changes clear private caches across tabs.

Remaining limitations:

- Clearing cookies can lose access to previous workspaces.
